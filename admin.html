Kết nối đặt lịch (Google Apps Script) quan trọng

Dán URL Web App bạn deploy từ Google Apps Script (xem hướng dẫn trong README.md). Để trống nếu chưa có — form đặt lịch sẽ tự chuyển sang chế độ đơn giản (chỉ ghi nhận thông tin, không hiện giờ trống).

Giờ làm việc (hiển thị trên website)

Phần này chỉ đổi chữ hiển thị trên trang (footer, trang chủ...).

Cấu hình đặt lịch thực tế (đồng bộ vào Google Sheet) real-time

Đây là cấu hình thật để hệ thống tính giờ trống — sẽ ghi thẳng vào tab "Cài đặt" trong Google Sheet qua Apps Script. Cần đã điền Apps Script URL ở tab "Tổng quan" và đúng giá trị dòng "Khoá bí mật quản trị" trong tab Cài đặt của Sheet.

Ví dụ: thời lượng 60 phút + nghỉ giữa 60 phút ⇒ lịch trống là 8:00–9:00, rồi 10:00–11:00... Đổi "nghỉ giữa" thành 30 phút ⇒ lịch cách nhau 1 tiếng rưỡi liên tục.

Không cần cắm Webhook (nếu bot đang có Webhook, vào app Zalo Bot bấm "Xoá Webhook" trước — 2 cách này không dùng cùng lúc được). Cách dùng: điền Bot Token ở trên → bấm nút dưới → hệ thống sẽ chờ tối đa 25 giây → ngay lúc đó mở Zalo và nhắn 1 tin cho bot (không nhắn trước khi bấm, phải nhắn trong lúc đang chờ mới bắt được).

Đồng bộ đội ngũ & chi nhánh sang lịch đặt hẹn

Danh sách bác sĩ/chi nhánh dùng để hiển thị trên site được chỉnh ở tab "Đội ngũ & chi nhánh". Bấm nút dưới đây để đẩy đúng danh sách đó sang Google Sheet (bảng Doctors/Branches) làm nguồn dữ liệu cho form đặt lịch.

Ảnh chính website

Ảnh được lưu trực tiếp trong content.json (định dạng base64) để không cần thao tác upload file riêng — đơn giản và luôn đồng bộ. Với nhiều ảnh chất lượng cao, file content.json sẽ nặng hơn, cân nhắc dùng link ảnh ngoài (dán URL) nếu cần tối ưu tốc độ tải.

Lịch hẹn sắp tới

Đọc trực tiếp từ Google Sheet qua Apps Script (cần đúng khoá bí mật đã nhập ở tab "Giờ làm & đặt lịch").

Cách A — Tải file, tự đẩy lên GitHub

Tải file content.json đã chỉnh, ghi đè vào file cùng tên trong repo của bạn rồi git add . && git commit -m "update content" && git push như bình thường.

Cách B — Lưu thẳng lên GitHub (tự động)

⚠️ Personal Access Token sẽ được lưu trong trình duyệt (localStorage) của máy này. Chỉ dùng trên thiết bị cá nhân, không dùng ở máy tính công cộng/dùng chung. Token chỉ cần quyền "repo contents" (read/write) trên đúng 1 repo này.

Chỉnh JSON trực tiếp

Dành cho các phần chưa có form riêng (ví dụ danh sách dịch vụ chi tiết). Sửa cẩn thận — sai cú pháp JSON sẽ không áp dụng được.
